## Trap: `|| 0` on a user input is a correctness bug, not a style choice

`apps/website/src/main.js` has **7** of these. An empty cost field becomes `0`, renders as
`$0.000`, and `roundsToBreakEven` renders **"0"** — which reads as *equipment is free* rather
than *unknown*. **No rendering test catches it, because `$0.000` renders perfectly.**

Generalises: **`x || 0` on any user-supplied value converts "not known" into a confident false
number.** In this repo the class extends to aggregates over sparse columns and to derived
figures computed before their inputs exist.

## Finding: "0/N populated" is often really "mixed", and mixed is worse

A brief said six dimensional columns were 0/229. Measured, six were 0/229 — but
`saami_max_psi` was **98/229**. A design that handles only the fully-empty case then renders
`0` beside real numbers in the same column. **A plausible number next to a blank is more
misleading than a uniformly blank column**, because the eye infers the blank means zero.

**Measure coverage claims before designing for them.** The headline count can be true and
still hide the harder case.

## Finding: licence restrictions are a distinct data state

`cip_max_bar` is 0/229 because CIP forbids reproduction without written approval
(`cartridge-dimensions/01-source-survey.md`). Rendering that as "not recorded" is **actively
false** — we have the source and may not copy it. Four absences, not one; the UI cannot infer
which, because a CSV cell carries only that it is empty.

## Trap: app-store weapons policies regulate SALE, not depiction

Google Play's "Dangerous Products" policy forbids facilitating **sale** of firearms and
**manufacture instructions**. Apple §1.1.3 targets *"reckless use"* and *purchase
facilitation*. **Neither prohibits depicting or analysing shooting.** The widely-assumed
"Google will ban a gun app" is not supported by either policy as written — though absence of
prohibition is not approval.

## Trap: the mail gate checks header FORMAT, not just timestamps

`npm run mail:check` rejected my inbox for two things I would not have caught by reading:

1. **A header I "restored" that I had never seen a valid example of.** I re-added a
   template line as `<!-- ... | TEMPLATE (pre-existing) -->`. The gate parses **every**
   `<!-- ... -->` block as a message header, so a decorative comment is a malformed header.
   **Do not put HTML comments in a mailbox unless they are real headers.**
2. **Timestamps going backwards.** I wrote `14:40` for a message sent after a `16:05` one
   because I was matching a clock reading rather than the real order.

**Timestamps must be monotonic in file order, and every comment block must parse as a
header.** Both are checked; neither is visible by reading.

## Reusable: a sample SD is biased LOW, and that bias direction matters

`E[sigma_hat] < sigma`: **−20.3% at n=2, −12.0% at n=3**, decaying as `1/(4n)`. Bessel corrects
the *variance's* mean bias; it does not make `sigma_hat` unbiased.

**Measured consequence:** a "2-sigma" threshold on a group mean fires **18.4% at n=3** against a
nominal 4.6% — four times promised. `sigma / sqrt(n)` is correct; **the estimate it is built
from is biased in the direction that makes rules fire more.**

Generalises to any "k-sigma" rule built on a small-sample estimate. **Verify the bias
direction before trusting a threshold**, because a low-biased denominator is worse than a
high-biased one: it produces false alarms, and often.

## Reusable: Monte Carlo needs a SEEDED RNG, or the check passes by luck

20,000 trials at σ=0.5, ratio 1.00 ± 0.008 — **but with `Math.random()` that number is a
different number every run, and a gate that can only confirm itself is not a gate.** A
mulberry32 PRNG plus a fixed seed made the result reproducible, which is also how I knew the
numbers were sound when the *formatting* broke.

**Seed the RNG. Then re-read the output file — a reproducible artifact nobody can read is not
evidence.**
